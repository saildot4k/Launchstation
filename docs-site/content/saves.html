Saves, PSU & Timestamp Tools

Launchstation keeps the classic memory-card/save toolbox while making destructive actions and timestamp manipulation more explicit.

Create an archive from a save

Select one individual PS1 save or a folder containing files and no subdirectories, then choose Copy or Cut. Browse to the output folder, open Options and choose Create archive.... Both browsers offer formats appropriate to the save in the clipboard:

Selected saveArchive choices
PS2 save folderPSU - PS2 save backup (EMS/wLE) or PSV - PS3 export
Individual PS1 saveMCS - PS1 save backup, PSV - PS3 export or PSX - Action Replay / GameShark

Choose the archive format, then confirm or edit the suggested filename. The archive is created in the folder you are browsing, including an empty folder. PSU and PS2 PSV retain the save's original folder/file names, attributes and timestamps. PSV exports include a PS3 signature; PS2 PSV also includes the icon.sys and icon references needed by the PS3. The suggested PSV filename uses the PS3 naming convention. For PS3 import, put it in PS3/EXPORT/PSV/ on USB storage. MCS stores one PS1 save with its original game filename and directory checksum. PSX stores one PS1 save in Action Replay format: a 54-byte header containing the original game filename, followed by the unchanged save data. PSX is a single-save archive; whole cards use Save card as instead. A PS1 backup folder containing the original save can also be archived.

Copy or Cut records the source path and file metadata immediately. Save contents are read only when Create archive or Extract is chosen. Those operations reuse the R3Z transfer checks to restore compatible source and destination drivers and HDD mounts as needed. An unavailable source or unmounted VMC must be reconnected or mounted again. Incompatible driver pairs, including MMCE with MX4SIO, are rejected before reading or writing save data. Create archive is available only after Copy or Cut of one PS1 save or one folder containing files and no subdirectories, and the current output folder is writable. Selecting an item alone does not enable it. A flat folder does not need icon.sys for PSU creation; PS2 PSV still requires valid icon.sys and its referenced icons. Folders with subdirectories, ordinary files, and multiple copied items leave Create archive unavailable. Copy retains the source. Cut removes it only after the archive is created and the source still matches the data read for that archive operation; if the source changed, became unavailable or cannot be removed, the archive is kept and a message explains that the source remains. Canceling or a failed archive write retains the source and clipboard. Existing archives are preserved; failed temporary writes are cleaned up. A PS1 card receives extracted PS1 saves rather than archive files.

Importing other save formats

Select one or more supported archives and choose Copy or Cut. Browse to the destination folder or compatible memory card, open Options and choose Extract PSU..., Extract PSV..., Extract MCS... or the corresponding clipboard extension. Archives of the same format share that extension label; a mixture of formats uses Extract saves.... Extraction writes directly into the current folder with no destination-picker popup. Selecting an archive alone does not enable extraction. Mount a VMC first to extract into it. PS1 saves restore directly at a PS1 card's root using their original game filename; no directory is created there.

Copy retains the original archives. Cut removes each unchanged source only after its save has been successfully extracted; failed or unverifiable removals retain the source and report it. If a batch stops, completed Cut items are removed from the clipboard and unprocessed items remain. Ordinary Paste copies or moves the original archive files.

Imports retain the game filename. Existing saves are left intact: back up and remove an existing save before importing its replacement. Invalid paths, incomplete archives and duplicate filenames are rejected before writing. Compressed and uncompressed save data are limited to 16 MiB per input; allocation failures are reported. Save metadata and timestamps are restored on PS2 cards and VMCs; ordinary storage folders keep the decoded files.

Copying saves

Copy/paste and PSU workflows retain the specialized handling required by memory-card folders. Avoid treating a PS2 save as an arbitrary PC directory when preserving icon metadata, attributes and timestamps matters.

Virtual memory cards

Both browsers can mount a selected image as vmc0:/ or vmc1:/. PS1 formats include VMP, MCR, VM1, BIN, VMC, GME, VGS, SRM and MCD. Mounting checks the contents and geometry, independently of the filename extension or its case. This also accepts PS2 MCD, MC2, VMC and other raw image names, and distinguishes PS1 from PS2 when the same suffix is used.

Every supported PS1 layout contains one 128 KiB card payload beginning with MC. Wrapped files are larger than 128 KiB and can be mounted directly. Changes retain the wrapper, update the VMP signature or GME directory tables as needed, and preserve unrelated header data.

PS2 images support both 512-byte data pages without ECC and 528-byte pages containing 512 bytes of data plus 16 spare bytes. For example, an 8 MiB card is 8,388,608 bytes without ECC or 8,650,752 bytes with ECC. ECC is stored per page, rather than in a separate image header. Writes regenerate the twelve ECC bytes from each changed page and retain its remaining spare bytes. Image length and superblock geometry must agree.

A PS1 card has sixteen 8 KiB blocks. One contains the directory; fifteen are available for saves. Both browsers show X of 15 blocks free for physical PS1 cards and mounted PS1 VMCs. A multi-block save consumes every block in its chain.

Real PS1 memory cards work in either PS2 memory-card slot through mc0:/ and mc1:/. Their contents are a flat list of saves, each using one or more blocks. Import writes the original game save filename directly at the card root, without a directory. Folder creation, folder pasting, PS2 icon/date tools, text editing and launch-argument actions are disabled on PS1 cards and PS1 VMCs.

Save a PS1 card for Ember or POPStarter

Select a PS1 image, or browse a physical PS1 card or mounted PS1 VMC, and choose Save card as.... Both browsers offer Raw image... for a custom filename and these emulator presets, followed by a destination folder picker:

EmulatorCard 1Card 2Folder
EmberMC1.vmcMC2.vmcgames/<game>/ beside that game's disc files
POPStarterSLOT0.VMCSLOT1.VMCThe game's VMC folder, normally POPS/<game>/

The Raw image option lets you enter the output filename after choosing a folder; emulator presets use their required names. Each output is a raw 128 KiB card, suitable for mounting and save imports. Raw, DexDrive GME, VGS and PSP VMP images can all be exported this way for emulators that require raw cards. Exporting a mounted VMC preserves the complete image, including deleted slots. Exporting a physical PS1 card rebuilds an image containing its active saves. Existing output files are preserved; choose another folder or back them up and rename them first.

Timestamp manipulation

Launchstation can edit and organize directory timestamps. This is especially useful for OSDSYS/HOSDSYS ordering and icon-based exploit folders whose position is influenced by timestamps.

Organizer roots

The organizer supports memory-card roots and hdd0:/__common/. Sorting modes include manual ordering, A–Z and SAS-style timestamps; game-save handling is kept distinct where appropriate. The native updater preserves an existing SAS date on its own app folder after updating the ELF and metadata, so its position does not need to be organized again.

Exploit-folder protection

Dangerous modifications/deletions of known exploit-style memory-card folders trigger warnings. That guard exists because a routine rename/delete can turn a bootable exploit card into an unbootable one.
