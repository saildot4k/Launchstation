Settings Reference

Dashboard settings are grouped by purpose and retain explicit unsaved-state behavior.

PS2 hardware clock

Use Settings > System > Set PS2 clock manually... and enter YYYY-MM-DD HH:MM:SS. Launchstation validates the date, writes the PS2 RTC and verifies the readback. The displayed date and time refresh immediately after a successful write. Network builds also offer Settings > Network > Sync PS2 clock from Internet. With a dead clock battery, the time may need setting again after power loss.

PS2 temperature

Settings > System > PS2 Temperature Units (50K and later) selects Celsius or Fahrenheit. On supported consoles, temperature appears two spaces after the time, with a degree symbol. The sensor is read every five seconds using the R3Z MECHACON command; if the first probe is unsupported, the temperature is hidden. Unit changes convert the cached sensor reading immediately. The choice is saved in DASHBOARD.CNF.

Colored Game ID launch bars

Game ID color output for ELF/application launches is off by default on new configurations. It remains available in Settings > Launching > Game ID output for RetroGEM-compatible display adapters. Previously saved configurations retain their selected value until changed.

Theme-matched controller button icons

Settings > Appearance > Control icon backings controls whether face-button and D-pad symbols receive a theme-derived badge. When disabled, the symbols render without the backing. Button symbols are generated from the built-in vector atlas and need no external icon PNGs.

Unsaved state

Settings compare current serialized values with the session snapshot. Touching a control and returning it to the original value does not leave a false dirty flag. Save failures remain visible and can be retried.

Path pickers

SELECT chooses the current folder in folder pickers; START opens the dashboard popup. Program/file settings use the native browser picker. POPStarter and Neutrino have explicit ELF path fields. Ember uses an Ember directory picker instead: the folder name/location is arbitrary, but the save-safe umbrella still contains ember.elf, bios.bin and games/<Game>/. When a selected game's own umbrella lacks ember.elf, the configured Ember directory can supply it to that device automatically. VCD remains POPStarter; CUE/BIN/EXE remains Ember.

Reset actions

Display/theme reset actions restore known project defaults so users do not need to manually reverse each visual setting.

Native update install

Settings > System > Check for updates validates ancestry against the rolling latest release. The updater selects the standard or DS34 PSU package for the running variant, verifies its advertised SHA-256 and contents over trusted HTTPS, stages the verified ELF and then replaces the running app's ELF using a .BAK rollback file. The verified four-file PSU can restore missing updater CA and BGM sidecars, but it does not overwrite existing customized sidecars. Interrupted .UPDATE/.PACKAGE staging files are preserved for manual recovery rather than silently truncated. Restart LAUNCHSTATION to execute the new build. Older update clients may require a one-time manual package install.

Current Home, Apps and Files placement

Back moves up settings pages and folders; the Settings root and Files device list no longer have a Home button. Use L1/R1 or START > Home to change sections. Home includes the Applications library and Last folder shortcut. In Home & applications > Start screen, choose Home, Applications, Files, Tools or Settings. Applications starts directly in Home's library viewer with All applications selected. Home also opens that viewer automatically when Recent applications is 0 and its saved history is empty. Files runs the native File Browser directly; separate Apps and Devices labels are retained only where the old internal section identifiers require compatibility. Tools is where classic MISC commands live.

Video mode confirmation

A changed video mode is previewed for 10 seconds, giving the display time to resync. Select Keep to retain it for this settings session; cancellation or no confirmation restores the previous mode and screen offsets. Save remains a separate action. The switch waits for outgoing graphics transfers and rendering to finish before resetting the GS, then refreshes the dashboard texture pool. NTSC, VGA and 480p use a 640×448 framebuffer; PAL, 576p and 576i use 640×512. The dashboard maps the same 640×448 layout to each framebuffer so panels, text, clipping and spacing keep their relative positions. To inspect a mode, choose Keep, browse Home, Files, Tools, Settings and the Text Editor, then return to Screen calibration to adjust position or select another mode. Progressive and VGA modes require a compatible display and connection. 576p and 576i are separate choices. Native 576p requires retail PS2 ROM 2.20 or newer, or a detected PSX/DESR console with ROM 1.80J or 2.10J. Unsupported 576p is grayed out in the chooser and skipped with Left/Right. 576i stays available and uses PAL at 50 Hz. If unsupported 576p or an invalid mode was saved, startup changes the selection to Auto before GS initialization and uses the console region. Both outputs use the same 10-second confirmation and rollback. PAL, 576p and 576i each reserve 2.5 MiB for two framebuffers, leaving 1.5 MiB for textures; oversized padded textures and palettes are rejected before allocation to keep the interface responsive.

Storage driver loading

Drivers load when a browser, application or tool needs the device. Per-device driver auto-start settings have been removed. Old Dash_DevAuto and Dash_ShowUnavailableDevices values are ignored and omitted on save. Eligible device families remain listed, and opening an unprobed device starts its existing lazy driver stack.

ELF device paths

Ordinary ELF launches use the fixed R3Z 4.80 policy: usb: and mass: become mass0:/..., and numbered USB/MASS paths become massN:/.... ATA and MX4SIO keep their device paths. The handoff-path selector has been removed; old Modern_Device_Handoff values are ignored and omitted on save.

Automatic start and Start screen

Start screen chooses the first view. A configured Settings > Launching > Automatic start & boot > Automatic start target runs afterward only when Automatic start timeout is greater than zero. A timeout of 0s disables automatic start while keeping the target saved, so the selected screen stays open. Held-button launch keys still work at 0s. Any button cancels a running countdown. Save Settings to keep your choice.

Startup application discovery

The cached application list in DASHLIB.CNF is loaded before the selected Start screen opens. When a library scan runs, it checks memory cards afresh even if an earlier status check reported them absent, and reads other devices whose drivers are already running. A failed card check preserves its cached applications for a later retry. The viewer shows scanning status until the result has been applied. Opening another device, launching an application, or using a storage tool loads the required driver on demand. Background scans skip unloaded stacks.
