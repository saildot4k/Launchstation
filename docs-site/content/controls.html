Controls

Button labels follow configured confirm/cancel mapping, so the face button can differ by region or preference.

Confirmation popups use the displayed face buttons directly: Confirm performs the named action, and Back/Cancel dismisses it. For example, Confirm clears recent applications and Cancel keeps the list. D-pad input does not select an action, and there is no selection highlight.

One-launch IOP override

When starting an ELF application, tap Confirm and release to use the saved Settings > Launching > Reset IOP before launch choice. Hold the configured Confirm button continuously for one second to use its opposite for this launch: On becomes keep IOP, and Off becomes reboot IOP. The hold progress shows both choices. The saved setting is unchanged, including if preparation is cancelled or the launch fails.

The choice is captured before application preparation. It also works with launch arguments. Keyboard and automatic launches without a held controller Confirm use the saved setting. Neutrino, POPStarter and Ember game-image launches retain their dedicated device-handoff policies.

Visible navigation

L1/R1 cycles Home, Files, Tools and Settings. Home contains Applications and Last folder; Files opens directly into a persistent native browser. Tools exposes individual built-in utilities. Automatic-start and launch-key target pickers retain MISC/. Returning to Files preserves the folder and selection.

Text Editor

See Text Editor navigation. L1/R1 moves to line boundaries with the keyboard hidden; L2/R2 pages vertically. With the virtual keyboard open, the D-pad selects keys and tilting the right stick moves the text cursor left/right and up/down. The compact footer keeps all six hints inside the dashboard safe width.
