Network & PC Integration

Network features are demand-loaded where practical so normal file-manager startup does not pay for an unused network stack.

FTP Server

Start Tools > FTP Server for file transfers. Launchstation starts a clean IOP session and prepares memory-card, USB, HDD/PFS, ATA and controller support before accepting connections. An absent HDD does not prevent serving the other devices.

The FTP screen shows the IP address, port, FTP connections, active transfers and current or last operation. Launchstation stays on this screen until you use the single Cancel action, mapped to your configured physical cancel button, to stop FTP. Open files and connections close before normal dashboard operation resumes. Stopping an active upload can leave a partial file.

FTP pathStorage
/mc0/, /mc1/Memory-card slots 1 and 2
/usb0/, /usb1/USB filesystem units 0 and 1
/hdd0/<partition>/HDD0 PFS partitions, such as __common
/ata0/ATA0 FAT/exFAT storage

The root lists available devices directly, without intermediate unit folders. The old family/unit FTP paths are no longer accepted.

On consoles that do not support HDD/ATA, FTP skips those drivers and omits their entries. Memory-card, USB, controller and Ethernet support remain available.

PFS mounting is automatic and stays behind the HDD path. MMCE, MX4SIO, shared mass aliases, direct pfs paths and additional units are outside the FTP scope. Memory-card polling, scans and other dashboard storage work pause during FTP.

Rename uses each filesystem's native operation. Cross-device rename and drivers without native rename support return an error.

Switching network modes

FTP Server, PC Host, UDPFS and Internet clients (including clock sync) use separate IOP sessions. Switching between them automatically reboots the IOP before loading the requested modules. Entering the FTP screen establishes a fresh session; other modes reuse their active session. Switching away stops FTP and invalidates open device handles; direct copies between Host and UDPFS are rejected before opening files.

Legacy PC remote workflows

The exclusive FTP screen provides file transfer only. Dashboard PC launch-command polling and the staged ISO receiver do not run while it is open.

PC game receiver / UDPFS

The legacy PC game receiver does not run in the exclusive FTP screen. UDPFS remains available through its own network mode. UDPFS is also an accepted Neutrino ISO backend when the filesystem/server and IP configuration are valid.

IP configuration

Network settings use the classic IP, netmask and gateway configuration model. The dashboard tracks unsaved network state separately and can write an updated IPCONFIG-style snapshot.

Internet clock synchronization

Use Settings > Network > Sync PS2 clock from Internet. It loads the Ethernet IP stack and socket RPC server when requested, then queries 0.pool.ntp.org. As in NTPS2, the client records the local timer when the time arrives and adds elapsed time before writing and verifying the PS2 hardware clock. It uses the saved IP, netmask and gateway; the gateway provides DNS with a public resolver as fallback when no resolver is already configured. The reply timeout is five seconds, with one retry for a failed request. A server refusal is not retried. Errors identify driver startup, DNS, socket, timeout or reply-validation failures. This action does not start FTP or netfs.

Failure isolation

  1. Confirm physical link and adapter initialization.
  2. Confirm IP/netmask/gateway.
  3. Confirm service/filesystem discovery.
  4. Only then debug FTP, UDPFS or another upper-layer feature.

Native HTTPS sockets have bounded connect/handshake/read/write waits. DNS resolution in PS2IP remains synchronous and is a separate hardware edge case.
