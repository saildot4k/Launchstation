File Browser

Files is a first-class, persistent dashboard tab using the native browser. Tools > Essentials > File Browser opens this same tab. Eleven rows fit above the status line and footer hints; classic wLaunchELF file operations remain supported through the shared backends.

Launching BIN/CUE, VCD or ISO game images does not add them to recent applications or schedule the shared favorites/history save. Recent applications set to 0 also prevents recording application launches.

Tab and folder continuity

Files opens directly into the browser without a separate landing page. L1/R1 switches top-level dashboard tabs; returning preserves the browser folder and selection. The Home tab provides the Last folder shortcut. Built-in utilities have individual entries under Tools.

Opening files

  • .PNG, .JPG, .JPEG — open in the native dashboard image viewer. PNG uses the existing bounded libpng decoder; JPEG uses a bounded libjpeg path derived from the historical wLaunchELF JPG support.
  • Image viewer controls: Left/Right browse other PNG/JPG/JPEG images in the current sorted folder (wrapping at either end), Up/Down rotate 90 degrees, L2/R2 zoom, left stick pans while zoomed, Square toggles fullscreen, Start toggles slideshow, L1/R1 changes the 1-60 second slideshow delay, Select resets the view, and Confirm/Back closes the viewer. Slideshow uses the same mixed-format folder order.
  • .ELF, .XLF, .KELF — executable launch path.
  • .VCD — POPStarter PS1 handoff.
  • .CUE, .BIN, PS1 .EXE — Ember when the image is directly inside <umbrella>/games/<Game>/. The umbrella name is not fixed.
  • .ISO — Neutrino PS2 handoff.
  • Text/config formats — dashboard Text Editor.
  • Folders — enter folder.

Ember handoff

USB Ember launches use a clean IOP handoff. Launchstation finishes background I/O and audio, resets the IOP, and rebuilds only the USB filesystem stack before starting Ember. The launcher deliberately does not reload its homebrew SIO2MAN/PADMAN modules; Ember loads the ROM pad modules itself. This avoids the hardware-observed pad init rc=-1 conflict while keeping the selected USB game tree mounted again before Ember starts.

Operations

Triangle opens contextual operations. Depending on device and file type, the browser can copy, cut, paste, rename, delete, create folders, calculate size, edit or organize timestamps, work with PSU saves, mount VMC images, edit text or invoke specialist tools.

Naming files and folders

New-folder, rename and Save As dialogs use the Text Editor's compact character layout and wide Space key. Symbols, Tab, Return and on-screen Del are omitted from naming dialogs; the controller delete shortcut remains available. Forward slash (/) and backslash (\) are hidden and cannot be typed with a USB keyboard. START accepts the name; Triangle cancels and restores the original text. Naming dialogs accept one line of text.

Selection

Square marks entries. Operations apply to the marked set; otherwise they apply to the focused entry. In the operations menu, Select all uses a checkmark with a small plus at the upper left, and Clear selection uses the matching checkmark with a minus at the upper left. Invert selection uses a filled rounded square with the entire central checkmark drawn as negative space. Classic exploit-protection checks remain for sensitive memory-card paths. System-update folder warnings name the target region: BIEXEC-SYSTEM is Japan, BAEXEC-SYSTEM is America/Asia, BEEXEC-SYSTEM is Europe, and BCEXEC-SYSTEM is China. Deleting or modifying an item inside one of these folders shows the same region warning.

Clipboard source

After Copy or Cut, the footer shows the matching Copy or Cut icon followed by the full source path for a single file or folder. Multiple selections show the icon followed by Assortment in <folder path>. The icon uses exactly the same color as the text, including when a theme applies a separate icon tint. Files and folders in the clipboard show outlined scissors for Cut or overlapping rounded squares for Copy in their source directory, including after returning to that folder. Clipboard icons and filenames keep the marked-selection color until the clipboard is cleared or replaced, including after navigating away and returning. The same symbols appear in the Cut and Copy menu entries. Paste with new names uses a pencil with a small plus in its upper-right corner. Marking an item shows its checkmark even if it is already in the clipboard. Unmarking it reveals its Cut or Copy symbol again while it remains in the clipboard. Long paths scroll within the available status line. The source stays visible when browsing to another destination; loaded launch arguments retain priority in that line.

Copy, move and paste progress

The transfer popup shows Pasting file X of N, the current filename, a rounded progress bar, copied bytes at its left and the current file's total size at its right, then average speed and remaining time. Both size labels use the same spacing below the bar as tab labels use below their icons. The speed and time rows move together with them. Both size labels use the same unit, chosen from the current file's total size: KB below 1 GB, MB below 1 TB, and GB for larger files (1024-based units). Amounts below 1 KB show fractional KB; larger KB amounts use whole numbers, such as 1200 KB. MB and GB retain two decimal places. The copied amount increases as data is written. Long filenames are shortened to fit the popup; the original names and paths are used for the transfer. Launchstation counts files before starting, including files inside selected folders and payload files inside PSU archives; folders and the PSU dot entries do not count as files. PSU creation and restoration use the same layout. The bar and time estimate apply to the current file, while average speed covers the whole paste operation. The retained R3Z 4.80 rate and time calculations are unchanged.

  • Current speed: bytes written since the previous progress sample, multiplied by 1000 and divided by the elapsed milliseconds.
  • Remaining time: after at least one second has elapsed since the previous sample, measure bytes written over that interval. The first valid sample initializes the estimate; later samples use (3 * previous rate + new rate) / 4. Divide the current file's remaining bytes by this smoothed rate, rounded down to whole seconds. No estimate is shown until the first valid sample; a sampled stall shows Unknown until data resumes.
  • Average speed: total copied bytes divided by the elapsed time since the paste operation started. This includes setup and other time between files.
  • Units: speeds use B/s or KB/s (1024 bytes per KB). Long estimates show hours, minutes and seconds.

Verification and deletion use their own progress displays without stale transfer rates. The rounded progress bar remains bounded to its track.

Sorting

The dashboard browser's Sort by popup lists Type, Name, Game title, Size, Date-Time, Extension, As stored in that order. Type is the startup default, including when no configuration file is found. A changed sort choice lasts for the current session. Extension sorts by filename suffix. Type keeps four groups in order: folders; ELF executables (including XLF and KELF); recognized text/config files; then all remaining files, including game images. Folders and executables use ascending filename order. Within the text/config and remaining-file groups, files are grouped alphabetically by extension, then alphabetically by filename within each extension. Matching is case-insensitive, including numbered names, with no direction prompt. Files without an extension lead the final group. Other sorted modes can be Ascending or Descending, with folders always first.

Classic File Browser: four display modes

The classic L1 mode menu now supports four upstream-compatible display modes: File names, File names + details, Game titles and Game titles + details. Circle switches between filename modes, while Square switches between title modes; each repeated press toggles the detail column. The game-title modes use existing title metadata and the Shift-JIS renderer, while the two no-details modes use the full row width. Filename/title sorting and ascending/descending controls remain independent.

The dashboard Files tab and its modal browser also provide filename/title modes with optional details. These display controls do not start a device scan or change storage initialization.

Classic file-browser improvements (October 2026)

The classic modal File Browser's L1 display/sort menu now supports reversible sorting: choose Filename (D-pad Down), Game title (Left) or Timestamp (Up); press the same direction again to reverse its order. Right selects No sort. Triangle returns to the browser. Folders remain ahead of files and ELF entries ahead of other files in both directions. The dashboard Files tab has its own independent sort selector, including the fixed-order Type grouping described above.

In memory-card save titles, Launchstation now respects icon.sys's title line-break offset for PS2 save folders and PSU archives, adding a separator without splitting Shift-JIS characters or duplicating existing spaces. The *Tuna Date operation for a selected real MC folder is now inside Folder dates..., with Manual, A-Z, Z-A and SAS ordering. It is deliberately absent when the selection is not an eligible physical memory-card folder; the older HDD/PFS date functions are unchanged.

Size and date-time

Size and date-time occupy independent columns with an explicit gutter. Seconds are retained. Filename width is calculated from actual metadata width so full timestamps fit rather than being shortened.

Root devices

Root entries use two left-aligned columns: the device path on the left and its description on the right. The Files tab and file/folder picker share this layout. USB entries appear immediately after Memory Card Slot 2. For example, mc0:/ shows Memory Card Slot 1, mmce0:/ shows SD2PSX SD Card Slot 1, and usbN:/ shows USB Storage. The list also covers both APA and exFAT HDD units, MX4SIO, CDVD, UDPFS, PC Host, PSX DVR, PSX Internal Flash (xfrom0:/), compatible PC CARD CF adapters, and mounted virtual memory cards. The automatic-start and launch-key target pickers retain a separate MISC/ entry for built-in commands. In the File Browser, device startup shows its operation title in the path bar where Choose a device or the current folder normally appears, without a progress popup. Internal memory-card synchronization and per-unit probe details stay hidden. A message is shown if no USB storage is found. Diagnostic status remains available in device tools. Current-folder paths in the browser and folder picker use numbered usbN:/ labels, including when the saved path uses mass:/ or massN:/. Display formatting does not change file operations or ELF handoffs. USB discovery does not assume a permanent mass0:.

Rows and navigation

The native browser and path picker show ten rows within the dashboard safe area, with centered scrolling where the list permits it. Up/Down wraps one item at a time. Left/Right pages to an endpoint before wrapping on the next press; subsequent presses resume paging. The classic browser retains its display-dependent capacity and existing endpoint-first paging.
